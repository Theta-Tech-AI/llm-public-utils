# Lessons and failure patterns

These rules come from observed multi-agent delivery failures. They are portable causes and corrections, not a claim that every campaign needs the same pool or tools.

| Observation | Cause | Correction |
|---|---|---|
| More authors produced more patches but fewer closures. | Review, CI repair, and publication were saturated. | Limit active delivery items; reserve reviewers; clear the ready queue before starting more code. |
| The coordinator kept planning improvements while ready work waited. | Process work had no delivery bound. | Make one small improvement aimed at the current bottleneck, apply it to the next item, and resume delivery. Delegate preparation around the coordinator's final decision, and measure the improvement by shorter queue age and more accepted outcomes rather than more process artifacts. |
| Many “easy” slices left the original tasks open. | Assignments optimized patch size instead of full acceptance. | Audit complete issue scope before selection; keep a per-row acceptance matrix. |
| A worker started an issue that was already closed. | Assignment used an old backlog snapshot. | Refresh task state, comments, claims, and linked work at assignment time. |
| A local branch appeared current but omitted a provider-side update. | A remote-tracking ref was treated as live state. | Refresh and verify the provider remote before calling a ref current. |
| A worker named after a model did not prove model identity. | Labels were mistaken for runtime metadata. | Record requested and observed identity, or explicitly mark it unverified. |
| An idle worker never acted on a new message. | The messaging operation did not restart a completed turn. | Use the runtime's follow-up/resume operation and confirm state change. |
| Nested or CLI workers created hidden load. | Only direct managed children were counted. | Track descendants, processes, memory, and shared environments in one capacity budget. |
| Temporary builds filled the filesystem and stopped even cleanup commands. | Retained compositions had no space budget or cleanup owner. | Check the actual filesystem before expansion; use an authorized workspace with enough capacity, retire owned disposable builds after recording revisions and evidence, and watch the size of what is retained. |
| A new patch landed in another task's delivery clone. | Ownership and workspace were implicit. | Put path, branch, baseline, and allowed scope in every assignment. Preserve the mistaken work and isolate the patch — verify that the final diff contains only the assigned task. |
| Validation passed against the wrong source. | Build directories were stale, or overlays contaminated the mirror. | Use immutable inputs and a distinct composition per check; record source revisions. For generated artifacts, compare fresh generator output with the shipped artifact, rather than loading the same artifact twice. |
| A “pre-existing” test failure disappeared after composition. | Baseline used an old disposable build. | Reproduce on fresh pristine inputs before classifying the failure. |
| Local typing passed but CI rejected the same test file. | Single-file inference and local settings differed from CI. | Match project-wide check scope, config, tool version, and dependencies. Confirm imports resolve and reproduce the known CI failure on the old revision before trusting a repaired local result. |
| Focused tests passed, but publication failed on cheap repository-wide checks. | The delivery plan omitted checks outside the changed module. | Read the required CI contract early; run its cheap applicable checks before publication, and watch whether failed publication attempts fall. Fix new violations without weakening checks. |
| Several ready items waited on the same prerequisite repair. | Each delivery path treated the shared blocker as separate work. | Assign one repair owner, then reuse the verified revision in dependent items. Recheck each final composition. |
| A gate printed PASS despite new type errors. | Typing was informational inside a broader gate. | Read the gate contract and its diagnostics; wait for required CI checks. |
| Tests passed while the production path bypassed the new abstraction. | Tests exercised only helpers or mocked the changed behavior. | Trace real callers and verify the changed observable behavior. |
| Review approved an old revision. | Amendments were not coupled to review records. | Record exact head; review the final delta and rerun affected checks. |
| An upstream update dropped previously consumed fixes. | The candidate was newer but on divergent ancestry. | Preserve consumed history/content and validate the final upstream-plus-overlay tree. |
| “Merged” appeared in a report while the PR remained open. | Narrative status was trusted without a fresh remote check. | Verify hosting-service state before reporting or closing — check the merge timestamp and merge revision. |
| A publication retry used a stale object manifest. | Requests were generated before the final amendment. | Regenerate from the final revision and verify returned object IDs. |
| Architecture cleanup deleted a meaningful seam or introduced a broad translator. | Line reduction replaced contract analysis. | Check consumers, packaging, invariants, and ownership; prefer the narrow correct change, and confirm the actual duplication fell. |
| A provider refactor retained duplicate selection variables. | Compatibility tests passed, but acceptance required one observable selection value. | Record the observable configuration contract before splitting resolver and config-writer work; allocate both sides against that contract, and do not call symbol centralization a full migration. |
| A local pass was reported as live acceptance. | Implementation, integration, deployment, and acceptance were collapsed. | Track and prove each required stage separately. |
| Reports survived only in temporary paths. | The recovery record was incomplete. | Persist the decision, revision, evidence summary, remaining scope, and next owner in the task tracker. |
| A 16-agent campaign had only one agent running while the coordinator reported 16. | Registered agents were counted after their turns completed; freed slots were not refilled. | Query live states before each capacity report and after completions; assign bounded useful follow-up work and confirm the new turn is running. Report any shortfall when safe work is unavailable. |
| All three workers completed while review and acceptance work remained, and refill was deferred during CI/deploy waiting. | The coordinator had no checkpoint to re-plan before waiting or sending status. | At completion, before CI/deploy waits, and before status replies, refresh capacity and ready work; give each freed slot an independent task or record its actual constraint. A wait alone does not block unrelated work. |
| A credential helper and a container environment dump printed live secrets into internal tool output. | Diagnostics requested whole secret-bearing payloads, and filtering after output missed values outside a `PASSWORD` pattern. | Request only needed non-secret metadata; filter inside the command before any tool output. After exposure, report its scope without repeating the value, follow the operator's decision on use or rotation, keep no raw secret values in tool output or artifacts, and record the containment decision. |
| A worker finished and nobody read its result. | Completed child results are not always delivered automatically; the coordinator kept working instead of yielding and reading the roster. | Read the live roster on a recorded cadence and at each checkpoint, recover undelivered results explicitly, and treat an assigned child that is neither running nor reported as an outstanding result to resolve rather than as still running. Watch for completed results left unread. |
| An "independent review" returned a verdict from the same actor that wrote the change. | Independence was treated as a role label rather than a property of the artefact. | Require an independent reviewing actor and record who authored and who reviewed. If the identity is shared, or independence cannot be established, record that limitation and leave independent review outstanding — disclosing a shared identity does not satisfy the requirement. Watch for a self-reviewed change whose record nonetheless shows a reviewer. |
| Every control-plane query failed while the worker kept working. | An exhausted API quota or rate limit turned state queries into errors that the worker did not surface. | Check the quota or rate-limit information the runtime exposes before dispatch, and record it when it is unavailable. Treat repeated state-query failures as a stop condition for the affected assignment: record the blocker and what establishes recovery, stop claiming verified progress, and continue only work that does not depend on the unreadable state. Watch for work advanced while state was unreadable. |
| Sessions were killed by the kernel in the middle of a wave. | Where memory exhaustion is the cause, the wave was sized against available slots rather than the host's memory. | Size parallel work against measured memory and real host capacity, and confirm whether a silent worker died rather than finished — a killed session leaves no final completion report, though its durable checkpoints may survive. Watch for silent workers that never resume. |
| A permission denial halted a slice, and the work was retried or handed to a peer. | A blocked call looked like a routing problem, so the natural workaround was to forward it rather than surface it. | Treat a denial as terminal for that slice: report the evidence, hand the operator the one command, and never retry it verbatim or delegate around it — a peer's execution is not the operator's consent. Watch for a repeat attempt or a peer receiving the denied action. |
| One unbounded worker process took down the whole shared host. | Concurrent agents shared a host and a multiplexer, and one runaway test grew until the kernel killed it along with every sibling session. | Enforce per-process time and memory caps on heavy or possibly diverging commands and isolate them; a fix is not applied until the offending process is confirmed terminated. Watch for a process that outlives its fix. |
| A worker that stopped was counted as a worker that finished. | A turn ceiling, an exhausted budget, or the worker's own background jobs ended the run with partial output that read like a complete report. | On any worker stop, verify the artifact or revision and resume explicitly by task id; never fold a partial report into campaign state. Watch for partial output entering a status report. |
| A review approved a change whose tests nobody executed. | The reviewer's environment lacked prerequisites, so approving on reported evidence was cheaper than running the suite. | Make runnable prerequisites a precondition for review tasks, and mark a verdict resting on reported rather than reproduced evidence as provisional. Watch for approvals carrying no execution. |
| Two workers wrote the same file and produced an add/add conflict. | The wave was planned by issue rather than by file ownership, so path collisions were invisible before dispatch. | Compute overlapping paths before each wave and serialize or single-own any file two assignments would write; check whether a repair task is still needed before spending a worker on it. Watch for repeat collisions and obsolete repairs. |
| A campaign's decisions vanished into repeated compaction. | Campaign state lived in the conversation, so each compaction forced the coordinator to re-derive ownership, agreements, and acceptance criteria. | Write plan, ownership, decisions, and acceptance criteria to durable artifacts as they happen, and treat anything recoverable only from the message log as non-durable. Watch for state re-derived after a compaction. |
| Every small fix voided an approval and serialized the gate. | Reviews were pinned to an exact revision behind an amend-then-re-review loop with no batching. | Batch small fixes into one revision before requesting review and cap the open fix-chains per branch. Watch for successive approvals on one branch. |
| A host crash erased uncommitted work in throwaway worktrees. | Green slices sat unpushed in ephemeral checkouts, so a host-level failure cost the whole slice. | Push each green slice as soon as it is green and cap concurrently test-running agents, so a host loss costs at most one slice. Watch for green work left unpushed. |

## Turn experience into an improvement

After a costly failure, identify the first missing fact that would have prevented the wasted work. Put that fact in the assignment, log, check, or handoff closest to the decision. Measure whether the change reduced rework or wait on the next items.

Write a narrow rule supported by the failure. Do not convert a temporary environment fault into a permanent product workaround, an example pool size into a universal limit, or a single campaign into a claimed speedup. Keep the entrypoint short; add details here only when they change future decisions. Periodically remove rules that are obsolete or already enforced by tooling.

Each table row is one lesson: the observation, its cause, and the correction. The evidence that would show the rule helped belongs in the correction when it changes a future decision — as a measured outcome or a failure to watch for — rather than in a separate cell. A lesson whose evidence cannot be stated is not yet supported; do not add it.
