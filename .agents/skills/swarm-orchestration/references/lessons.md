# Lessons and failure patterns

These rules come from observed multi-agent delivery failures. They are portable causes and corrections, not a claim that every campaign needs the same pool or tools.

| Observation | Cause | Operational correction | Evidence to watch |
|---|---|---|---|
| More authors produced more patches but fewer closures. | Review, CI repair, and publication were saturated. | Limit active delivery items; reserve reviewers; clear the ready queue before starting more code. | Closures/hour, review age, accepted work, rework. |
| The coordinator kept planning improvements while ready work waited. | Process work had no delivery bound. | Make one small improvement aimed at the current bottleneck, apply it to the next item, and resume delivery. Delegate preparation around the coordinator's final decision. | Shorter queue age and more accepted outcomes, rather than more process artifacts. |
| Many “easy” slices left the original tasks open. | Assignments optimized patch size instead of full acceptance. | Audit complete issue scope before selection; keep a per-row acceptance matrix. | Remaining rows and actual task closures. |
| A worker started an issue that was already closed. | Assignment used an old backlog snapshot. | Refresh task state, comments, claims, and linked work at assignment time. | No duplicate implementation. |
| A local branch appeared current but omitted a provider-side update. | A remote-tracking ref was treated as live state. | Refresh and verify the provider remote before calling a ref current. | Provider-side head and local ref agree. |
| A worker named after a model did not prove model identity. | Labels were mistaken for runtime metadata. | Record requested and observed identity, or explicitly mark it unverified. | Runtime receipt, not agent self-report. |
| An idle worker never acted on a new message. | The messaging operation did not restart a completed turn. | Use the runtime's follow-up/resume operation and confirm state change. | Acknowledgment or active run. |
| Nested or CLI workers created hidden load. | Only direct managed children were counted. | Track descendants, processes, memory, and shared environments in one capacity budget. | Actual active count and resource usage. |
| Temporary builds filled the filesystem and stopped even cleanup commands. | Retained compositions had no space budget or cleanup owner. | Check the actual filesystem before expansion; use an authorized workspace with enough capacity and retire owned disposable builds after recording revisions and evidence. | Free space, free inodes, and retained build size. |
| A new patch landed in another task's delivery clone. | Ownership and workspace were implicit. | Put path, branch, baseline, and allowed scope in every assignment. Preserve the mistaken work and isolate the patch. | Final diff contains only the assigned task. |
| Validation passed against the wrong source. | Build directories were stale, or overlays contaminated the mirror. | Use immutable inputs and a distinct composition per check; record source revisions. For generated artifacts, compare fresh generator output with the shipped artifact, rather than loading the same artifact twice. | File hashes, composition manifest, reproducible checks. |
| A “pre-existing” test failure disappeared after composition. | Baseline used an old disposable build. | Reproduce on fresh pristine inputs before classifying the failure. | Same failing test and same context on baseline. |
| Local typing passed but CI rejected the same test file. | Single-file inference and local settings differed from CI. | Match project-wide check scope, config, tool version, and dependencies. Confirm imports resolve and reproduce the known CI failure on the old revision before trusting a repaired local result. | Changed-file diagnostics in the full context. |
| Focused tests passed, but publication failed on cheap repository-wide checks. | The delivery plan omitted checks outside the changed module. | Read the required CI contract early; run its cheap applicable checks before publication. Fix new violations without weakening checks. | Fewer failed publication attempts and less CI repair time. |
| Several ready items waited on the same prerequisite repair. | Each delivery path treated the shared blocker as separate work. | Assign one repair owner, then reuse the verified revision in dependent items. Recheck each final composition. | One repair, fewer duplicate investigations, and reduced blocked time. |
| A gate printed PASS despite new type errors. | Typing was informational inside a broader gate. | Read the gate contract and its diagnostics; wait for required CI checks. | Explicit type result and final required-check state. |
| Tests passed while the production path bypassed the new abstraction. | Tests exercised only helpers or mocked the changed behavior. | Trace real callers and verify the changed observable behavior. | Production consumer and relevant boundary test. |
| Review approved an old revision. | Amendments were not coupled to review records. | Record exact head; review the final delta and rerun affected checks. | Reviewed revision equals delivered revision. |
| An upstream update dropped previously consumed fixes. | The candidate was newer but on divergent ancestry. | Preserve consumed history/content and validate the final upstream-plus-overlay tree. | Ancestry, required content, composed tests. |
| “Merged” appeared in a report while the PR remained open. | Narrative status was trusted without a fresh remote check. | Verify hosting-service state before reporting or closing. | Merge timestamp and merge revision. |
| A publication retry used a stale object manifest. | Requests were generated before the final amendment. | Regenerate from the final revision and verify returned object IDs. | Exact final tree/commit and intended feature ref. |
| Architecture cleanup deleted a meaningful seam or introduced a broad translator. | Line reduction replaced contract analysis. | Check consumers, packaging, invariants, and ownership; prefer the narrow correct change. | Preserved behavior with less actual duplication. |
| A provider refactor retained duplicate selection variables. | Compatibility tests passed, but acceptance required one observable selection value. | Record the observable configuration contract before splitting resolver and config-writer work; allocate both sides against that contract, and do not call symbol centralization a full migration. | One accepted selection value and tests for the contract. |
| A local pass was reported as live acceptance. | Implementation, integration, deployment, and acceptance were collapsed. | Track and prove each required stage separately. | Deployed revision and real acceptance artifact. |
| Reports survived only in temporary paths. | The recovery record was incomplete. | Persist the decision, revision, evidence summary, remaining scope, and next owner in the task tracker. | A new session can resume without chat or local files. |
| A 16-agent campaign had only one agent running while the coordinator reported 16. | Registered agents were counted after their turns completed; freed slots were not refilled. | Query live states before each capacity report and after completions; assign bounded useful follow-up work and confirm the new turn is running. Report any shortfall when safe work is unavailable. | Running count from the runtime, slot assignments, and accepted issue closures. |
| All three workers completed while review and acceptance work remained, and refill was deferred during CI/deploy waiting. | The coordinator had no checkpoint to re-plan before waiting or sending status. | At completion, before CI/deploy waits, and before status replies, refresh capacity and ready work; give each freed slot an independent task or record its actual constraint. A wait alone does not block unrelated work. | Live roster, next assignment or constraint per freed slot, and movement in review or acceptance. |
| A credential helper and a container environment dump printed live secrets into internal tool output. | Diagnostics requested whole secret-bearing payloads, and filtering after output missed values outside a `PASSWORD` pattern. | Request only needed non-secret metadata; filter inside the command before any tool output. After exposure, report its scope without repeating the value and follow the operator's decision on use or rotation. | No raw secret values in tool output or artifacts; containment decision recorded. |

## Turn experience into an improvement

After a costly failure, identify the first missing fact that would have prevented the wasted work. Put that fact in the assignment, log, check, or handoff closest to the decision. Measure whether the change reduced rework or wait on the next items.

Write a narrow rule supported by the failure. Do not convert a temporary environment fault into a permanent product workaround, an example pool size into a universal limit, or a single campaign into a claimed speedup. Keep the entrypoint short; add details here only when they change future decisions. Periodically remove rules that are obsolete or already enforced by tooling.
