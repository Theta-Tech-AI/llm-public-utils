# Lessons: delivery, review, and acceptance

Failures in proving work: the source, the checks, the review, the merge, and the closure. These are portable causes and corrections, not a claim that every campaign needs the same pool or tools.

Each row is one failure: the observation, its cause, the correction, and the evidence to watch. The policy for evidence lives at the end of [lessons: execution](lessons-execution.md).

| Observation | Cause | Correction |
|---|---|---|
| A local branch appeared current but omitted a provider-side update. | A remote-tracking ref was treated as live state. | Refresh and verify the provider remote before calling a ref current. Evidence to watch: Provider-side head and local ref agree. |
| Validation passed against the wrong source. | Build directories were stale, or overlays contaminated the mirror. | Use immutable inputs and a distinct composition per check; record source revisions. For generated artifacts, compare fresh generator output with the shipped artifact, rather than loading the same artifact twice. Evidence to watch: File hashes, composition manifest, reproducible checks. |
| A “pre-existing” test failure disappeared after composition. | Baseline used an old disposable build. | Reproduce on fresh pristine inputs before classifying the failure. Evidence to watch: Same failing test and same context on baseline. |
| Local typing passed but CI rejected the same test file. | Single-file inference and local settings differed from CI. | Match project-wide check scope, config, tool version, and dependencies. Confirm imports resolve and reproduce the known CI failure on the old revision before trusting a repaired local result. Evidence to watch: Changed-file diagnostics in the full context. |
| Focused tests passed, but publication failed on cheap repository-wide checks. | The delivery plan omitted checks outside the changed module. | Read the required CI contract early; run its cheap applicable checks before publication, and watch whether failed publication attempts fall. Fix new violations without weakening checks. Evidence to watch: Fewer failed publication attempts and less CI repair time. |
| A gate printed PASS despite new type errors. | Typing was informational inside a broader gate. | Read the gate contract and its diagnostics; wait for required CI checks. Evidence to watch: Explicit type result and final required-check state. |
| Tests passed while the production path bypassed the new abstraction. | Tests exercised only helpers or mocked the changed behavior. | Trace real callers and verify the changed observable behavior. Evidence to watch: Production consumer and relevant boundary test. |
| Review approved an old revision. | Amendments were not coupled to review records. | Record exact head; review the final delta and rerun affected checks. Evidence to watch: Reviewed revision equals delivered revision. |
| An upstream update dropped previously consumed fixes. | The candidate was newer but on divergent ancestry. | Preserve consumed history/content and validate the final upstream-plus-overlay tree. Evidence to watch: Ancestry, required content, composed tests. |
| “Merged” appeared in a report while the PR remained open. | Narrative status was trusted without a fresh remote check. | Verify hosting-service state before reporting or closing — check the merge timestamp and merge revision. |
| A publication retry used a stale object manifest. | Requests were generated before the final amendment. | Regenerate from the final revision and verify returned object IDs. Evidence to watch: Exact final tree/commit and intended feature ref. |
| Architecture cleanup deleted a meaningful seam or introduced a broad translator. | Line reduction replaced contract analysis. | Check consumers, packaging, invariants, and ownership; prefer the narrow correct change, and confirm the actual duplication fell. Evidence to watch: Preserved behavior with less actual duplication. |
| A provider refactor retained duplicate selection variables. | Compatibility tests passed, but acceptance required one observable selection value. | Record the observable configuration contract before splitting resolver and config-writer work; allocate both sides against that contract, and do not call symbol centralization a full migration. Evidence to watch: One accepted selection value and tests for the contract. |
| A local pass was reported as live acceptance. | Implementation, integration, deployment, and acceptance were collapsed. | Track and prove each required stage separately. Evidence to watch: Deployed revision and real acceptance artifact. |
| An "independent review" returned a verdict from the same actor that wrote the change. | Independence was treated as a role label rather than a property of the artefact, and one shared identity puppets every agent, so "reviewer" carried no distinguishing identifier. | Require an independent reviewing actor and record who authored and who reviewed, as structured fields the delivery gate can compare. If the identity is shared, or independence cannot be established, record that limitation and leave independent review outstanding — disclosing a shared identity does not satisfy the requirement, and a finding marked unverifiable must not contribute to a pass. Watch for a self-reviewed change whose record nonetheless shows a reviewer. |
| A review approved a change whose tests nobody executed. | The reviewer's environment lacked prerequisites, so approving on reported evidence was cheaper than running the suite. | Make runnable prerequisites a precondition for review tasks, and mark a verdict resting on reported rather than reproduced evidence as provisional. Watch for approvals carrying no execution. |
| Every small fix voided an approval and serialized the gate. | Reviews were pinned to an exact revision behind an amend-then-re-review loop with no batching. | Batch small fixes into one revision before requesting review and cap the open fix-chains per branch. Watch for successive approvals on one branch. |
| Two concurrent writers raced on one shared integration branch. | Rebase-then-push against a mutable shared target has no per-branch reservation, and each accepted merge invalidates every other branch at once. | Fetch and rebase immediately before push, push only with force-with-lease, exclude agent-owned branches from bulk refresh sweeps, and re-read the head after the base moves. Watch for repeat non-fast-forward rejections. |
| A merge landed carrying conflict-marker text that nobody inspected. | Approval verified the source branch and the success of the merge command, never the content of the merge result on the target ref. | After every merge, fetch the target ref and check the changed files for conflict markers before treating the merge as delivered. Watch for merges whose result was never read back. |
| A run reported a successful terminal status having produced almost nothing. | The status vocabulary folds partial progress into warnings, so a near-empty run reads as success unless the caller checks populated counts. | Assert on produced-versus-expected counters before accepting any success status, and never roll a run's status into a progress total on its own. Watch for completions with empty or near-empty output. |
| A gate reported a false pass and a false failure on the same change. | Concurrent runs shared one hardcoded scratch tree and overwrote each other mid-build. | Make every tool's scratch and output path unique per run, and treat a gate result as invalid if another run wrote the same tree. Watch for gate results that contradict a clean re-run. |
| A partially executed run was reported as verified. | A consent or permission gate blocked one step and the rest of the run continued, so the summary read as fully verified. | Require every report to list steps skipped for denied consent or permission as an explicit unverified-gap section, and have the reviewer treat an unnamed skipped step as unverified. Watch for a verified claim that covers a step that did not execute. |
