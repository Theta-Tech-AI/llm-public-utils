# Lessons: workers and resources

Failures in running, resourcing, and keeping workers alive: identity, host limits, cancellation, and silent degradation.

Each row is one failure: the observation, its cause, the correction, and the evidence to watch.

| Observation | Cause | Correction |
|---|---|---|
| A worker named after a model did not prove model identity. | Labels were mistaken for runtime metadata. | Record requested and observed identity, or explicitly mark it unverified. Evidence to watch: Runtime receipt, not agent self-report. |
| An idle worker never acted on a new message. | The messaging operation did not restart a completed turn. | Use the runtime's follow-up/resume operation and confirm state change. Evidence to watch: Acknowledgment or active run. |
| Nested or CLI workers created hidden load. | Only direct managed children were counted. | Track descendants, processes, memory, and shared environments in one capacity budget. Evidence to watch: Actual active count and resource usage. |
| Temporary builds filled the filesystem and stopped even cleanup commands. | Retained compositions had no space budget or cleanup owner. | Check the actual filesystem before expansion; use an authorized workspace with enough capacity, retire owned disposable builds after recording revisions and evidence, and watch the size of what is retained. Evidence to watch: Free space, free inodes, and retained build size. |
| A new patch landed in another task's delivery clone. | Ownership and workspace were implicit. | Put path, branch, baseline, and allowed scope in every assignment. Preserve the mistaken work and isolate the patch — verify that the final diff contains only the assigned task. |
| Several ready items waited on the same prerequisite repair. | Each delivery path treated the shared blocker as separate work. | Assign one repair owner, then reuse the verified revision in dependent items. Recheck each final composition. Evidence to watch: One repair, fewer duplicate investigations, and reduced blocked time. |
| Reports survived only in temporary paths. | The recovery record was incomplete. | Persist the decision, revision, evidence summary, remaining scope, and next owner in the task tracker. Evidence to watch: A new session can resume without chat or local files. |
| A 16-agent campaign had only one agent running while the coordinator reported 16. | Registered agents were counted after their turns completed; freed slots were not refilled. | Query live states before each capacity report and after completions; assign bounded useful follow-up work and confirm the new turn is running. Report any shortfall when safe work is unavailable. Evidence to watch: Running count from the runtime, slot assignments, and accepted issue closures. |
| All three workers completed while review and acceptance work remained, and refill was deferred during CI/deploy waiting. | The coordinator had no checkpoint to re-plan before waiting or sending status. | At completion, before CI/deploy waits, and before status replies, refresh capacity and ready work; give each freed slot an independent task or record its actual constraint. A wait alone does not block unrelated work. Evidence to watch: Live roster, next assignment or constraint per freed slot, and movement in review or acceptance. |
| A credential helper and a container environment dump printed live secrets into internal tool output. | Diagnostics requested whole secret-bearing payloads, and filtering after output missed values outside a `PASSWORD` pattern. | Request only needed non-secret metadata; filter inside the command before any tool output. After exposure, report its scope without repeating the value, follow the operator's decision on use or rotation, keep no raw secret values in tool output or artifacts, and record the containment decision. |
| Every control-plane query failed while the worker kept working. | An exhausted API quota or rate limit turned state queries into errors that the worker did not surface. | Check the quota or rate-limit information the runtime exposes before dispatch, and record it when it is unavailable. Treat repeated state-query failures as a stop condition for the affected assignment: record the blocker and what establishes recovery, stop claiming verified progress, and continue only work that does not depend on the unreadable state. Watch for work advanced while state was unreadable. |
| Sessions were killed by the kernel in the middle of a wave. | Where memory exhaustion is the cause, the wave was sized against available slots rather than the host's memory. | Size parallel work against measured memory and real host capacity, and confirm whether a silent worker died rather than finished — a killed session leaves no final completion report, though its durable checkpoints may survive. Watch for silent workers that never resume. |
| A permission denial halted a slice, and the work was retried or handed to a peer. | A blocked call looked like a routing problem, so the natural workaround was to forward it rather than surface it. | Treat a denial as terminal for that slice: report the evidence, hand the operator the one command, and never retry it verbatim or delegate around it — a peer's execution is not the operator's consent. Watch for a repeat attempt or a peer receiving the denied action. |
| One unbounded worker process took down the whole shared host. | Concurrent agents shared a host and a multiplexer, and one runaway test grew until the kernel killed it along with every sibling session. | Enforce per-process time and memory caps on heavy or possibly diverging commands and isolate them; a fix is not applied until the offending process is confirmed terminated. Watch for a process that outlives its fix. |
| A worker that stopped was counted as a worker that finished. | A turn ceiling, an exhausted budget, or the worker's own background jobs ended the run with partial output that read like a complete report. | On any worker stop, verify the artifact or revision and resume explicitly by task id; never fold a partial report into campaign state. Watch for partial output entering a status report. |
| Two workers wrote the same file and produced an add/add conflict. | The wave was planned by issue rather than by file ownership, so path collisions were invisible before dispatch. | Compute overlapping paths before each wave and serialize or single-own any file two assignments would write; check whether a repair task is still needed before spending a worker on it. Watch for repeat collisions and obsolete repairs. |
| A campaign's decisions vanished into repeated compaction. | Campaign state lived in the conversation, so each compaction forced the coordinator to re-derive ownership, agreements, and acceptance criteria. | Write plan, ownership, decisions, and acceptance criteria to durable artifacts as they happen, and treat anything recoverable only from the message log as non-durable. Watch for state re-derived after a compaction. |
| A host crash erased uncommitted work in throwaway worktrees. | Green slices sat unpushed in ephemeral checkouts, so a host-level failure cost the whole slice. | Push each green slice as soon as it is green and cap concurrently test-running agents, so a host loss costs only the work not yet pushed rather than a whole wave. Watch for green work left unpushed. |
| A worker was judged finished from an unscoped process listing. | Processes are invisible across isolation boundaries — containers, namespaces, remote hosts, or a runtime that owns its workers — and silence was read as absence of work. | Confirm completion from authoritative lifecycle evidence: the exit status or terminal receipt of the run that launched it. Do not infer absence from a process listing whose scope you have not established. Watch for duplicate dispatch of work that was already running. |
| Concurrent workers sharing one per-user tool profile retargeted each other. | The client keeps active-identity state in a per-user config, so one unscoped switch is global rather than per-process, and it fails silently. | Give each worker an isolated profile or a pinned exported identity, and forbid bare identity-switch commands in worker briefs. Watch for calls landing under the wrong identity. |
| A second worker silently renamed its branch instead of failing. | A branch can be checked out in only one worktree, so handing the same branch name to two workers makes the second fail or divert without surfacing an error. | Allocate a unique branch and worktree name per worker up front, and require workers to fail loudly rather than rename when the requested branch is taken. Watch for diverted branch names appearing in reports. |
| Two workers editing one submodule collided despite separate worktrees. | A worktree isolates the superproject index only; submodule objects and checkouts remain shared. | Treat submodules and shared caches as single-writer resources: serialize edits to them or clone them per worktree. Watch for submodule conflicts between parallel workers. |
| A background subsystem failed thousands of times in silence. | Auxiliary work such as checkpointing degrades at warning level, which does not block the happy path and so is never acted on. | Turn repeated non-fatal background failures into an actionable signal by count or threshold, so a broken recovery mechanism cannot be discovered only at the moment recovery is needed. Watch for the same warning repeating without an owner. |
