# Issue Standards

## Required fields
Each Linear issue is required to have the following fields / labels:
- Project
- Issue Title
- Detailed Description
- Links or supplemental material or images as needed
- Very clear "what does done look like?"
- Assignee
- Due Date
- Priority
- Size estimate label
- Project-specific labels as applicable — e.g. a client or source label for agencies/consulting, an area or component label for products. Don't be shy on labels; they help clarify an issue, and it's OK to create a new one when the project's workflow needs it.

These apply whenever an issue is touched, not just at creation: if you pick up an issue (start, continue, close) and find required fields missing or the done criteria unclear, fix that before proceeding.

## Status honesty
The status must reflect reality at all times, not clear the board or flatter progress:
- **In Progress** means someone is actually working it. Starting work moves it there; pausing for the day does NOT move it back.
- **Blocked** (or the team's equivalent) means blocked — link the blocking issue.
- **Closed states are not interchangeable:** Done (done criteria met, with evidence), Canceled, Duplicate (link the surviving issue), or Won't Fix. Pick the one that honestly describes what happened.
- Due dates that have become unrealistic get updated and flagged to the user, not silently ignored.
- Status changes travel with a comment explaining them (see comment-rules.md) — a bare status flip with no comment is bad hygiene.
