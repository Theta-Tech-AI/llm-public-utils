# Orient
## Purpose
This is especially useful if you haven't run the linear skill recently, such as the start of a new session. It brings you up to speed on the projects, issues, and code you'll be working with. 

## Checklist
1. **Linear MCP:** Check the connection works with a cheap read call; if it doesn't, set it up per [connect.md](connect.md).
2. **Projects:** Get familiar with which projects the user is associated with. Which other users are part of that project, which types of issues are you responsible for versus others, and it may help to generate a paragraph you run by the user regarding their role in projects.
3. **Issues:** Get a sense of both open issues and closed issues for this user. What is due soon? What is overdue? You can ask the user questions at this phase.
4. **Code:** Read the latest commits, perhaps fetch from GitHub, and get a sense for what is happening recently with regard to the code.

Once you get through this checklist, you should have a clear understanding of what is going on, and then ask the user any clarifying questions to understand what they're working on.

## Quick Orient (mid-task)
Other actions (create, close, start, continue, stop) reference this section instead of repeating it. When you're about to act on an issue:
- If you need to, get your bearings on the list of projects, the list of issues, the list of users, and any other read-only info before acting.
- Ask the user clarifying questions when things are ambiguous, preferably as multiple choice selectors instead of raw input. Asking clarifying questions is optional, not required — skip it when the answer is obvious.
- Don't assume you know the correct project or issue unless it's very clear. If ambiguous, give the user a multiple choice selection over the candidates (projects, or matching issues) rather than guessing. Never act on an issue you only guessed at.
