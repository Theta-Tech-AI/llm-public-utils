# Create Linear Issue
1. **Connect:** Connect to Linear MCP (if it is not up or authorized, set it up per [connect.md](connect.md)).
2. **Orient:** Get your bearings and pick the right project, per the Quick Orient section of [orient.md](orient.md). If no existing project fits, offer to create a new one.
3. **Understanding:** Make sure you deeply understand from the user what this issue is they want you to create why it's important what done looks like and how they want the description in linear to be ask clarifying questions here again preferably as multiple-choice over freeform text but do what you need to do to clarify the issue you're creating. Again asking the user clarifying questions is optional, not required.
4. **Dedupe:** There might be an existing open issue for this, or a similar or related issue. Decide if it's better for you to comment on another issue and tell the user that or reopen an old issue or just provide comments to related issues. Typically, you will be creating a new issue, but it helps to understand if there's not an existing issue already created for this task. You might need to exit this loop early here if so, and render something for the user that says so if you go this route, which again should be rare but could happen sometimes.
5. **Create:** Create a new Linear issue via MCP, with every required field per [issue-standards.md](issue-standards.md).
6. **Comment:** Add any context that didn't fit the description as a comment, per [comment-rules.md](comment-rules.md) — links, screenshots, the conversation that spawned the issue.
7. **Rendering Ticket:** After the issue is created, render it for the user per [render-ticket.md](render-ticket.md).
