# Linear Issues Skill

## Getting situated
Run these at the start of a session (or whenever lost):
- [Connect](references/connect.md) to set up and verify the Linear MCP connection — read only if the connection is missing or misbehaving
- [Orient](references/orient.md) to get your bearings on projects, issues, and recent code (read or run this first usually)

## Issue lifecycle
The actions on a single issue, in the order they happen in an issue's life:
- [Create Issue](references/create-linear-issue.md) — a new issue is born
- [Start Issue](references/start-linear-issue.md) — pick it up and begin work
- [Continue Issue](references/continue-linear-issue.md) — resume after a pause
- [Stop Issue](references/stop-linear-issue.md) — pause without closing (e.g. stopping for the day)
- [Close Issue](references/close-linear-issue.md) — finish it out with the right resolution

## Maintenance
Cross-cutting upkeep of the whole board, outside any one issue's lifecycle:
- [Hygiene](references/hygiene.md) to audit issues for gaps and make sure Linear stays well-behaved

## Shared policies
Referenced by the lifecycle actions and maintenance above — never duplicated into them:
- [Issue Standards](references/issue-standards.md) for required fields and status honesty — the contract every action checks against
- [Comment Rules](references/comment-rules.md) for how and when to comment on issues — be heavy on comments
- [Render Ticket](references/render-ticket.md) for how to display a ticket to the user after acting on it

When the user loads the skill fresh, you may want to ask them what to do via a multiple choice selection, or describe what you're capable of doing. Subsequent invocations of this Linear Issues skill may know what the user wants based on what they've been working on lately, or maybe have a limited multiple choice selector, or maybe a guided wizard.
